# EELOG Generator - 仲裁模拟日志生成器

> 适用范围：用于生成模拟日志，以便学习日志结构和进行离线调试。
> 本工具为纯前端单文件应用，无需安装、无需联网，双击即用，不会上传任何数据。

## 1. 快速开始

1. 打开本目录下的 **`index.html`**（双击即可，支持 `file://` 本地直接打开）。
2. 第 1 步选择任务模式：**防御 / 镜像防御 / 拦截 / 资源回收 / 中断 / 生存**。
3. 第 2 步选择任务节点（下拉列表会按模式筛选；不预设任何节点生息基准），填写 1-4 个队员名。
4. 第 3 步填写期望生息（选择“/小时”或“/分钟”）、清场效率（可留空）和轮数。
5. 先点**“推算预览”**查看计算结果，再点**“生成并下载 EE.log”**，文件会自动命名为 `EE.log`。

## 2. 参数说明

| 参数 | 说明 |
|---|---|
| 任务模式 | 防御按波输入（标准 81 波 = 27 轮，单轮约 82 秒，上限 90 波）；镜像防御按轮输入（标准 9 轮，单轮约 503 秒，上限 12 轮）；拦截按争夺轮输入（标准 10 轮，单轮约 414 秒，上限 12 轮）；资源回收按净化段输入（默认 6 段，约 90 秒/段）；中断按目标轮输入（默认 8 轮，约 90 秒/轮）；生存按生命支持轮输入（默认 6 轮，约 300 秒/轮）。后 3 项按样本覆盖程度保守设定，可手动覆盖总时长 |
| 任务节点 | 原有 42 个节点保留；新增仲裁索引中的资源回收 1 个、中断 6 个、普通生存 23 个节点；所有节点不预设生息基准，只用于选择任务类型、地图和派系 |
| 队伍成员 | 最终固定 4 人。第 1 个视为主机。留空的槽位自动填充 7–15 位随机英文名 |
| 期望生息 | 以用户输入值作为全 Buff 目标直接参与无人机估算，不读取任何节点预置基准。无人机取整或达到模式预算上限时，预览显示实际计算结果 |
| 任务总时长 | 留空时自动估算（各模式节拍见上表，并带平滑浮动）；也可手动输入，例如 `37:45`、`1h7m50s`、`2264`（秒）。纯数字小于 300 时按分钟处理。输入会锁定预览与生成文件的总时长 |
| 清场效率 | 手动填写时，会直接决定有效敌人事件数；留空时按当前模式、轮数、时长和生息自动估算。定义为无人机出现率相对理论 20% 的达成率。`Spawned` 峰值仅用于完整性对照 |
| 轮数 | 防御填波数（自动按 3 波一轮换算）；镜像、拦截、资源回收、中断、生存分别填循环段、争夺轮、净化段、目标轮、生命支持轮。切换模式会载入各自默认值和上限 |

页面中把鼠标悬浮在每个选项的 `?` 或卡片上，会弹出同样的文字说明。

## 3. 样本与曲线口径

- 六种模式使用同一套平滑插值器，但各自拥有独立的压力锚点。锚点影响逐轮敌人权重、无人机分布、同时活跃数量、高压事件比例和事件间隔；小幅随机扰动保留在单条事件上。
- 六张模式卡片和任务预览显示统一尺寸、统一坐标尺度的固定参考相位曲线；生成器共享相同的模式锚点和插值规则，每次生成会抽取新的压力相位，因此不会复用预览中的逐事件轨迹。
- 事件时间使用低频、连续的小幅漂移叠加 ±1.3% 局部抖动；活跃数量按较慢的收敛速度更新，减少逐事件锯齿。曲线表示相对压力，不代表游戏内绝对敌人数或任务进度百分比。
- 防御样本包含 9 个波次和 3 次结算，约 248 秒有效任务段，支持保留约 82 秒/轮的节拍。
- 拦截样本包含 48 条 TerritoryMission 事件，敌人事件集中在任务后段；该样本没有清晰的逐轮结算边界，因此保留原有 414 秒节拍，只用样本校准密度曲线。
- 镜像防御样本只有两段约 81–112 秒的短记录，不能代表标准 9 轮任务；保留原有 503 秒节拍，曲线按循环阶段生成。
- 资源回收按 `MT_PURIFY` 与 SolNode167 关卡路径筛选。样本活动段长度分散且多为短片段，约 90 秒只作为默认合成阶段，不当作完整奖励周期；完整敌潮没有被该样本覆盖，所以复用了六份样本中已出现的 Infested 敌人类型。
- 中断按 `MT_ARTIFACT`、SolNode177 与 `SentientArtifactMission` 阶段筛选。样本含许多短任务片段，默认 90 秒为目标组的合成节拍，不推断为完整奖励间隔。
- 生存样本有效任务段约 301 秒，包含 12 个生命支持标记；用约 300 秒作为一轮，并按生命支持脉冲组织压力曲线。
- 新增模式节点名、系统、任务类型与派系来自本机 `Ws-Web-3d-tilesets/time/data/arbys.nodes.zh.json`；与该项目的仲裁索引对照后，资源回收有 1 个、中断有 6 个、普通生存有 23 个匹配项；SolNode309 的“联结生存”是独立任务类型，因此不列入普通生存。
- 所有模式的所有节点均不预设节点生息率，样本是否存在都不会改变这一点。期望生息完全采用用户输入并参与无人机估算；由于取整和预算上限，实际回显值可能略低于输入目标。“生息效率”比例因没有节点基准而不计算。样本节点 SolNode167、SolNode177、SolNode711 保留对应真实样本中的关卡路径；其余新节点按星球地图族与任务类型后缀推断路径，六份样本没有逐节点验证这些推断路径。
- 非样本节点的敌人池按节点派系从已有样本中观察到的类型模板分流；这不是每个仲裁节点的真实敌潮清单，未覆盖派系仍属于模拟模板。
- 新模式标准节拍的合成无人机预算上限约为资源回收 10,668/时、中断 12,084/时、生存 10,210/时。实际封顶值会随所选轮数和总时长变化，预览会显示封顶后的实际值。

## 4. 计算方式

- 轮次：防御、镜像防御和拦截沿用各自的轮次事件；资源回收与中断按 Purify / SentientArtifact 任务状态阶段推进，生存按 `SurvivalReward` 结算。新增模式的中段不套用旧模式的通用继续对话。主机时长 = `SS_STARTED → 末次模式结算`。
- 全 Buff 生息 = 无人机 × 0.06 × 5.9 + 轮次保底与红利（前 4 轮每轮 +0.21，之后每轮 +0.30）。页面会根据期望、轮次和时长估算无人机数。
- 清场效率 = 无人机 ÷（有效敌人 − 无人机）÷ 0.2 × 100。页面会据此估算有效敌人事件数，再按波次预算写入逐怪记录；`Spawned` 计数持续递增，仅用于完整性对照。
- 所有节点均无预设基准，因此不计算“生息效率”比例。期望生息输入值作为无人机估算目标；实际值会受无人机整数取整、确定性微扰和模式预算上限影响，并在预览中回显。
- 事件节奏加入有界、平滑的随机起伏。留空时，总时长和清场效率会按当前参数自动估算；手动填写时长或清场效率后，对应结果会严格采用输入值。

## 5. 生成文件的结构

- **启动头**：集群、构建、版本、缓存与连接等基础信息，以及关卡加载和登录流程。
- **大厅**：组队行、节点滚动、投票/任务名行（含 `_EliteAlert` 后缀）、关卡资源路径（含模式关键字）、实体创建、开局状态切换。
- **任务体**：防御包含波次预算与逐怪生成；拦截包含点位争夺；镜像防御包含环波；资源回收包含净化目标阶段；中断包含干扰目标组；生存包含生命支持脉冲。六种模式都会写入连续变化的敌人/无人机事件和自己的阶段结算。
- **收尾**：结算回调、经验/信用行、统计上传与档案写回。

## 7. 常见问题

- **页面动效没加载？** 确认 `vendor/` 与 html 在同一目录下且未改名；无动画时表单与生成功能不受影响。
- **生成大轮次很慢？** 镜像/拦截的单轮时间较长，生存也会持续生成多个生命支持阶段；行数多属正常，进度条会显示合成进度。
- **解析出的数值与输入差一点？** 时间抖动与取整会导致 ±1% 级偏差，生成结果面板会回显“实际达成”值，以该值为准。
- **文件名？** 固定为 `EE.log`。
